

# Что мы решили — простыми словами

## Два окна вместо одного монолита

Сейчас у тебя одно гигантское окно на 1175 строк, которое пытается быть всем сразу — и пультом управления, и настройками, и логом. Мы разделяем это на два окна с чёткими ролями.

**Первое окно — «Пульт управления» (Dashboard).** Это маленькое компактное окно, примерно 420 на 320 пикселей, которое ты видишь постоянно во время работы. Оно показывает самое важное: что сейчас делает ассистент (спит, слушает, думает, говорит), уровень микрофона с линией порога (чтобы видеть, «слышит» ли Шурочка), последний обмен репликами с таймингами (сколько заняли STT, LLM, TTS), четыре кнопки быстрых действий (слушать, стоп, дежурный режим, рекалибровка), строку здоровья внизу с тремя точками-индикаторами (STT, LLM, TTS — зелёный или красный). Также прямо в пульте есть выпадающий список для быстрой смены модели LLM — это самое частое действие, и ради него не нужно лезть в настройки. Если что-то пошло не так, внизу появляется строка-уведомление с последним предупреждением. Кликнул — открылся полный лог.

**Второе окно — «Настройки» (Settings).** Открывается по кнопке-шестерёнке из пульта. Это большое окно (800 на 600 минимум) с двумя зонами: слева — вертикальный список категорий (как в настройках VS Code или Windows), справа — панель с параметрами выбранной категории. Сверху — строка поиска.

## Почему именно боковая панель, а не вкладки сверху

При 80 параметрах, разбитых на 7 категорий, горизонтальные вкладки просто не помещаются — названия длинные, начинается скролл. Боковая панель (sidebar) масштабируется вертикально, ты видишь все категории одновременно, и это привычный паттерн из IDE и профессионального софта.

## Строка поиска — главная фича настроек

При 80 параметрах даже при идеальной группировке ты иногда не помнишь, в какой категории лежит нужная настройка. Набираешь «timeout» в поиске — и видишь все параметры со словом timeout из всех категорий, причём под каждым показаны хлебные крошки: «LLM → Ollama → OLLAMA_TIMEOUT», чтобы понимать контекст.

## Семь категорий настроек

Все 80 параметров из config.py разложены по семи группам.

**Общие** — пути к папкам, уровень логирования, ротация логов. Вещи, которые меняешь один раз при установке.

**Аудио и VAD** — шумоподавление DeepFilterNet (вкл/выкл), параметры калибровки, порог паузы, энергетические пороги. Здесь же живая визуализация уровня микрофона с линией порога — двигаешь слайдер и сразу видишь, как порог смещается относительно реального сигнала.

**Распознавание речи (STT)** — всего четыре параметра: провайдер, модель Whisper, устройство (CPU/GPU), язык. Коротко и ясно.

**Языковая модель (LLM)** — провайдер (Ollama или LM Studio), и в зависимости от выбора показываются только релевантные настройки. Выбрал Ollama — видишь URL и модель Ollama. Выбрал LM Studio — видишь URL и модель LM Studio. Не нужно видеть оба набора одновременно. Здесь же таймауты, лимит токенов и системный промпт — он большой, поэтому живёт в сворачиваемом текстовом поле с кнопкой «сбросить к умолчанию».

**Синтез речи (TTS)** — аналогично: выбираешь Silero или XTTS, видишь только настройки выбранного движка. У Silero — голос, качество, интонации, ударения. У XTTS — голос, WAV-файл для клонирования. Рядом с выбором голоса — кнопка «Тест», чтобы послушать, как звучит.

**Wake-word и команды** — кодовое слово, алиасы (вводятся как теги-чипы, а не текстовая строка), таймауты, параметры бипов. И внизу — таблица всех зарегистрированных команд с колонками: имя, тип, синонимы, статус. Таблица сортируется, фильтруется, по ней можно искать. Клик по строке показывает подробности команды.

**Интерфейс** — оверлей (вкл/выкл, позиция, прозрачность), трей, горячая клавиша, IPC.

## Двухуровневые секции: основное сверху, детали — в «Дополнительно»

Внутри каждой категории параметры разделены на два уровня. Основные — всегда видны. Редкие и технические (частоты бипов, retry delays, размер чанка) — спрятаны под сворачиваемую секцию «Дополнительно». Правило простое: если в секции пять параметров или меньше — она всегда раскрыта; если больше или там есть крупные элементы вроде текстового поля — она сворачивается. При этом состояние (раскрыта/свёрнута) запоминается между сессиями: если ты раскрыл «Дополнительные параметры VAD» — при следующем открытии они останутся раскрытыми.

## Три типа настроек по способу применения

Каждый параметр в интерфейсе помечен значком, показывающим, что произойдёт после его изменения.

Значок молнии (⚡) — применяется мгновенно, без перезагрузки. Сюда относятся wake-word, таймауты, уровень логирования, системный промпт, пороги VAD, параметры бипов, настройки оверлея.

Значок вращения (🔄) — требует перезагрузки компонента. Это смена модели LLM, смена голоса TTS, переключение провайдера LLM или TTS. Занимает несколько секунд, UI показывает спиннер с текстом «Перезагрузка TTS...».

Значок предупреждения (⚠) — требует полного перезапуска пайплайна. Это смена модели Whisper, смена устройства STT, изменение sample rate. При сохранении таких параметров появляется диалог: «Изменение требует перезапуска. Перезапустить сейчас?» с вариантами «Да / Позже / Отмена».

## Визуальные подсказки для изменённых параметров

Если параметр отличается от значения по умолчанию, его подпись выделяется жирным шрифтом (как в VS Code Settings). Ты сразу видишь, что кастомизировано. Правый клик по любому параметру — «Сбросить к значению по умолчанию».

## Валидация прямо в интерфейсе

Ввёл невалидное значение — поле подсвечивается красной рамкой с подсказкой, что не так. Кнопка «Сохранить» неактивна, пока есть ошибки. Валидация работает через Pydantic, который уже есть в зависимостях проекта.

## Переход с Tkinter на PySide6

Текущий Tkinter заменяется на PySide6. Причины: нативные таблицы (для команд), полноценная стилизация через QSS (как CSS для Qt), потокобезопасные сигналы (вместо ручных вызовов `after()` в Tkinter), sidebar и сложные лейауты без костылей. Лицензия LGPL — можно использовать свободно.

## Тёплая палитра Solarized Light

Для стилизации используется пакет `qtvscodestyle`, в котором уже есть тема Solarized Light — подключается одной строкой. Палитра адаптирована под требования: никакого фиолетового и синего. Фон — тёплый кремовый (#fdf6e3), панели — чуть темнее (#eee8d5), текст — спокойный серо-голубой (#657b83). Главный акцентный цвет — горчично-жёлтый (#b58900), он используется для активных элементов, кнопок, фокуса полей ввода. Для статусов: зелёный — всё хорошо, оранжевый — предупреждение, красный — ошибка, бирюзовый — информация (вместо синего). Шрифты: Segoe UI для текста, Consolas для значений параметров — оба предустановлены на Windows, ничего дополнительно ставить не нужно.

## Новая система хранения настроек

Сейчас config.py — это файл с константами, которые нельзя менять из программы. Мы его рефакторим: дефолтные значения остаются в коде (Pydantic-модель), а пользовательские настройки сохраняются в файл settings.toml. TOML выбран потому, что поддерживает комментарии и читается человеком (в отличие от JSON). В settings.toml попадают только те параметры, которые ты изменил — файл остаётся компактным. Кнопка «Открыть settings.toml» в окне настроек позволяет редактировать файл напрямую в текстовом редакторе, если предпочитаешь.

## Таблица команд

Загружается из CommandRegistry в рантайме. Показывает все зарегистрированные команды: имя, тип (обычная, мгновенная, составная), все синонимы-фразы, которыми можно вызвать команду, статус. Можно фильтровать по типу, искать по тексту, сортировать. Кнопка «Обновить» перечитывает реестр. В будущем сюда можно добавить пользовательские команды из YAML-файла.

## Порядок реализации

Сначала рефакторинг config.py в Pydantic-модель и настройка PySide6 с темой. Потом Dashboard. Потом окно настроек с семью панелями. Потом таблица команд и полировка (live VAD preview, кнопка «Тест» для TTS, захват горячей клавиши). В конце — удаление старого Tkinter-кода и интеграция с существующими overlay и tray.
