# Docs Keeper Skill (shura v2)

Скилл загружает контекст для актуализации двух главных документов проекта.

## Ключевые файлы документации

| Файл | Назначение | Кто пишет |
|------|-----------|-----------|
| **`CHANGELOG.md`** | Хронология изменений по категориям Added/Changed/Fixed/Removed | Агент `docs-keeper` |
| **`PROJECT_INDEX.md`** | Карта проекта: пакеты, модули, точки входа, описания файлов | Агент `docs-keeper` (для новых файлов читает содержимое и пишет описание) |
| `README.md` | Витрина GitHub — обновляется **вручную** перед `git push` на основе CHANGELOG | Не трогать автоматически |
| `MIGRATION_PLAN.md` | Дорожная карта M1–M8 — это **план**, не журнал | Не трогать |
| `LLM_report.md`, `docs/VOICE_AI_*.md`, `soft-sniffing-allen.md` | Внешние/исторические документы | Не трогать |

## Когда ОБЯЗАТЕЛЬНО вызывать

- Добавлен новый `.py` модуль в любой пакет (`commands/`, `core/`, `ipc/`, `system/`, `ui/`, `players/`, `utils/`, `tests/`, `scripts/`).
- Добавлена новая голосовая команда (новый класс в `commands/`, регистрация в `commands/registry.py`).
- Изменён публичный API провайдера (`STTProvider`, `LLMProvider`, `TTSProvider`) или сигнатура IPC-метода.
- Добавлен/изменён агент, скилл или хук в `.claude/`.
- Завершён и принят очередной `check_stage_<N>.py` (стейдж M1–M8 или config-refactor).
- Добавлен новый тестовый файл в `tests/`.
- Добавлен/изменён ключевой параметр `config.py` (новый провайдер, новые таймауты wake-word, BT-фильтры и т.п.).
- Исправлен значимый баг в pipeline, wake-word, командах, UI или IPC.

## Когда НЕ нужно вызывать

- Минорные правки внутри функции без изменения API.
- Эксперименты в `__pycache__`, `logs/`, `models/`.
- Правки `.txt`-черновиков в корне (`новые фичи.txt`, `список пожеланий.txt` и т.п.).
- Изменения в `.claude/projects/*/memory/` — это память Claude.

## Что проверяет агент

```
git status + git diff           →  что изменилось в репозитории
ls по пакетам                   →  реальная структура (commands/, core/, ipc/, system/, ui/, players/, utils/, tests/)
CHANGELOG.md [Unreleased]       →  уже зафиксированные изменения
PROJECT_INDEX.md                →  что устарело в карте проекта (таблицы, дерево)
README.md                       →  ТОЛЬКО АУДИТ — отчёт о расхождениях, не редактировать
```

## Формат записи в CHANGELOG

```markdown
## [Unreleased] — YYYY-MM-DD HH:MM

### Added
- `module.py` — описание зачем добавлен

### Changed
- `core/wake_word.py` — что изменилось и зачем

### Fixed
- `commands/note.py` — что было сломано, как исправлено
```

## Особенности проекта

- **check_stage_<N>.py** удаляются после ручной приёмки — это правильный момент зафиксировать «Stage N принят» в `[Unreleased]`.
- В корне есть `.txt`-черновики (планы фич) — игнорировать.
- Отдельной секции `BREAKING` для внешних клиентов нет — у проекта нет публичных потребителей API.
- README обновляется отдельно перед `git push` на основе накопленного `[Unreleased]`.
