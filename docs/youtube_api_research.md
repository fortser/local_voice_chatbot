# YouTube: управление через браузер и интеграция с API

Исследование возможностей для проекта «Шурочка». Сводка двух ответов: горячие клавиши и управление просмотром, затем различия YouTube API key и OAuth. Функции и квоты внешнего сервиса могут меняться; перед реализацией следует сверить официальную документацию.

## 1. Управление YouTube во время просмотра

На компьютере YouTube поддерживает горячие клавиши плеера. В новом интерфейсе YouTube сначала нужно щёлкнуть по плееру, чтобы клавиши сработали. Список актуальных сочетаний открывается через `Shift + ?`.

| Возможность | Управление | Идея для Shurochka |
|---|---|---|
| Пауза/воспроизведение | `K` | Голосовые команды паузы и продолжения. |
| Перемотка | `J`/`L` — 10 секунд; стрелки на полосе прогресса — 5 секунд | Перемотка на стандартный или настраиваемый интервал. |
| Переход по главам | `Ctrl + ←`/`Ctrl + →` в Windows | Следующая/предыдущая глава, если у видео есть главы. |
| Покадровый просмотр | `,`/`.` при паузе | Перейти на предыдущий/следующий кадр. |
| Скорость | `<`/`>` | Замедлить или ускорить видео. Для выбора конкретного значения используется меню плеера. |
| Полный экран | `F`; выйти можно `F` или `Esc` | Голосовое переключение полноэкранного режима и обратно. |
| Мини-плеер | `I` | Свернуть плеер в мини-окно YouTube. |
| Субтитры | `C` — включить/выключить | Голосовое включение субтитров; язык выбирается в меню. |
| Поиск YouTube | `/` фокусирует строку поиска | Ввести запрос голосом и запустить поиск. |
| Следующее/предыдущее видео | `Shift + N` / `Shift + P` | Навигация по видео; предыдущее работает в плейлисте. |

Источники: [официальный список горячих клавиш](https://support.google.com/youtube/answer/7631406?hl=en), [изменение размера плеера](https://support.google.com/youtube/answer/6052392?hl=en).

### Полный экран и режим театра

Полноэкранный режим официально переключается клавишей `F`, а выйти можно `F` или `Esc`. YouTube также предлагает режим театра: плеер становится шире, но страница и рекомендации остаются видны. Режим театра не указан в текущем официальном списке горячих клавиш. Клавиша `T` встречается в старых справочных обсуждениях, поэтому её работу следует проверять в целевом браузере; надёжный запасной способ — нажать кнопку режима театра на странице.

Источник: [Change video player size](https://support.google.com/youtube/answer/6052392?hl=en).

### Комментарии, лайки и подписки

- Комментарий можно подготовить в поле под видео и опубликовать кнопкой. Автор видео может отключить комментарии или ограничить, кто может их оставлять. Комментарий публичен, поэтому безопасный голосовой сценарий — подготовить текст, показать/прочитать его и отправить только после подтверждения пользователя. [Справка YouTube о комментариях](https://support.google.com/youtube/answer/6000964?hl=en-GB)
- Лайк ставится кнопкой под плеером. [Справка YouTube о лайках](https://support.google.com/youtube/answer/6083270?hl=en-MP)
- Подписка оформляется через кнопку канала. [Справка YouTube о подписках](https://support.google.com/youtube/answer/4489286?hl=en-GB)
- API позволяет выполнять эти действия при OAuth-авторизации. Комментарии могут быть недоступны из-за настроек ролика/канала или ограничений аккаунта. [API: комментарии](https://developers.google.com/youtube/v3/guides/implementation/comments), [API: подписки](https://developers.google.com/youtube/v3/docs/subscriptions/insert)

### Идеи активного поведения во время просмотра

1. **Заметка с временной меткой:** при команде приостановить видео, сохранить скриншот, текст заметки, ссылку и позицию ролика.
2. **«Запомни этот момент»:** сохранить ссылку на видео с текущей временной отметкой, чтобы потом быстро вернуться.
3. **Пересказ фрагмента:** получить доступный текст субтитров/расшифровки рядом с текущей позицией и передать его локальной LLM для краткого объяснения.
4. **Поиск по расшифровке:** искать термин в транскрипте и переходить к соответствующей временной позиции. YouTube показывает транскрипт для видео с субтитрами; нажатие на строку ведёт к этому месту ролика. [Справка о транскриптах](https://support.google.com/youtube/answer/15930243?hl=en)
5. **Режим обучающего просмотра:** переходить по главам, замедлять и покадрово изучать видео.
6. **Продолжение после вопроса:** сохранить позицию видео перед ответом ассистента, чтобы вернуться к тому же месту.

### Предлагаемые этапы реализации

- **Первый этап:** прямые горячие клавиши плеера: пауза, перемотка, полный экран, субтитры, скорость, мини-плеер и навигация по видео. Проверять, что фокус находится в нужном плеере/вкладке.
- **Второй этап:** режим театра, переход к комментариям, меню качества и выбор языка субтитров. Такие действия зависят от навигации по элементам страницы и могут ломаться при изменении интерфейса YouTube.
- **Отдельный этап:** API-операции с аккаунтом (лайк, комментарий, подписка, плейлисты) с OAuth. Для публикации комментария запрашивать отдельное подтверждение.

## 2. API-ключ и OAuth: различия и применение

### Кратко

- **API-ключ** идентифицирует проект-приложение и подходит в основном для чтения публичных данных YouTube.
- **OAuth** позволяет пользователю войти в Google и явно предоставить приложению доступ к действиям от имени своего YouTube-аккаунта.
- API-ключ не разрешает ставить лайки, публиковать комментарии или менять пользовательские плейлисты. Для таких операций требуется OAuth.

Источник: [YouTube Data API: начало работы](https://developers.google.com/youtube/v3/getting-started).

| Возможность | API-ключ | OAuth |
|---|---:|---:|
| Поиск публичных видео и каналов | Да | Да |
| Получение публичного названия, описания, длительности и статистики | Да | Да |
| Чтение пользовательских данных, например собственных плейлистов | Нет | Да |
| Добавление доступного чужого видео в свой плейлист | Нет | Да |
| Поставить/снять лайк | Нет | Да |
| Подписаться на канал | Нет | Да |
| Опубликовать комментарий | Нет | Да, если разрешено автором видео и аккаунту пользователя |
| Управлять уже открытой вкладкой браузера | Нет | Нет, OAuth сам по себе этого не делает |

Публичные сведения о видео доступны без пользовательской авторизации. Некоторые части ресурса (например, детали обработки и файла) доступны только владельцу видео. [Videos: list](https://developers.google.com/youtube/v3/docs/videos/list)

OAuth позволяет выполнять операции от имени аккаунта для видео любых авторов, если это допускают настройки и права. Например, можно лайкнуть видео, добавить его в свой плейлист или подписаться на канал. [Оценки видео](https://developers.google.com/youtube/v3/guides/implementation/ratings), [добавление в плейлист](https://developers.google.com/youtube/v3/guides/implementation/playlists), [подписки](https://developers.google.com/youtube/v3/docs/subscriptions/insert).

Для публикации комментариев необходим OAuth. Настройки канала/ролика всё равно могут ограничить возможность комментировать. [Комментарии YouTube API](https://developers.google.com/youtube/v3/guides/implementation/comments)

## 3. Как получить API-ключ

1. Войти в [Google Cloud Console](https://console.cloud.google.com/) и создать проект.
2. В **APIs & Services → Library** включить **YouTube Data API v3**.
3. В **APIs & Services → Credentials** создать **API key**.
4. Ограничить ключ используемым API; хранить локально и не публиковать в репозитории.

Это наиболее простой первый шаг для поиска видео и чтения открытой информации. Ключ внутри распространяемого приложения нельзя считать секретом: его можно извлечь. Для личного приложения ограничение ключа API и отсутствие в Git снижают риск случайной утечки/злоупотребления.

## 4. Как подключить OAuth

1. Включить YouTube Data API v3 в Google Cloud проекте.
2. Настроить экран OAuth-согласия и целевую аудиторию.
3. Создать OAuth-клиент типа **Desktop app**.
4. Для тестирования добавить свой Google-аккаунт в список тестовых пользователей.
5. При первом подключении Shurochka откроет системный браузер. Пользователь войдёт в Google и разрешит запрошенные функции.
6. Приложение получит краткоживущий access token и при необходимости refresh token. Пароль Google приложение не получает.

Для настольных приложений Google рекомендует системный браузер и локальный loopback redirect. [OAuth для настольных приложений](https://developers.google.com/youtube/v3/guides/auth/installed-apps)

### Токены, разрешения и режим тестирования

- Запрашивать только необходимые OAuth scopes. YouTube scopes могут давать довольно широкий доступ к аккаунту и операциям с видео, комментариями и оценками. Перед согласием Google показывает пользователю запрошенные разрешения.
- Refresh token хранить в защищённом локальном хранилище, например Windows Credential Manager или другом подходящем хранилище секретов. Не помещать токен в Git, обычные логи или общедоступный конфиг.
- Для внешнего приложения в статусе Testing авторизация тестового пользователя, включая refresh token при offline-доступе, может истекать через 7 дней. Для продолжительного использования нужно учитывать повторную авторизацию и требования к публикации/проверке OAuth-приложения. [Сроки действия OAuth-токенов и авторизаций](https://developers.google.com/identity/protocols/oauth2#expiration)

## 5. Квоты и ограничения

На момент исследования официальная документация указывает для нового проекта отдельный лимит до **100 вызовов `search.list` в день** и **10 000 единиц квоты в день** для большинства остальных методов. По 50 единиц стоят некоторые операции: добавление видео в плейлист, публикация комментария, лайк и подписка. Квоты могут меняться; текущее использование отображается в Google Cloud Console. [Таблица квот YouTube API](https://developers.google.com/youtube/v3/determine_quota_cost)

Другие ограничения:

- публичное чтение не раскрывает все приватные данные владельца;
- лайки, подписки и комментарии выполняются от лица OAuth-аккаунта;
- возможность прокомментировать зависит от настроек автора и ограничений аккаунта;
- API-ключ/OAuth для Data API не управляют автоматически кнопками плеера в произвольной вкладке браузера.

## 6. API данных и управление проигрывателем — разные интеграции

**YouTube Data API** работает с данными и аккаунтом: поиск, метаданные, плейлисты, подписки, лайки, комментарии и некоторые операции владельца канала.

Для управления воспроизведением во встроенном YouTube-плеере существует **YouTube IFrame Player API**. Он позволяет воспроизводить/приостанавливать ролик, перематывать, управлять громкостью и скоростью, получать события плеера и сведения о воспроизведении. Он управляет плеером, встроенным в приложение или веб-страницу, а не автоматически любой уже открытой вкладкой браузера. [YouTube IFrame Player API](https://developers.google.com/youtube/iframe_api_reference)

Для обычного внешнего браузера остаются горячие клавиши или браузерная автоматизация. Для автоматизированного режима браузерной вкладки нужно отдельно определить способ надёжно найти целевую вкладку и проверить фокус; автоматизация интерфейса зависит от изменений страницы.

## 7. Рекомендация для проекта «Шурочка»

Для текущего Windows/Python приложения лучше поэтапная комбинированная интеграция:

1. **API-ключ** для публичного поиска и чтения метаданных.
2. **Горячие клавиши** для уже открытого ролика во внешнем браузере.
3. **OAuth как необязательная функция** для своих плейлистов, лайков, подписок и комментариев. Публикацию комментария подтверждать отдельно.
4. **IFrame Player API**, если позже появится собственный экран/область со встроенным YouTube-плеером и нужна надёжная синхронизация текущей позиции и команд воспроизведения.

Python-интеграция поддерживается Google; Quickstart отдельно показывает API-ключ для публичных запросов и OAuth-клиент Desktop app для действий, требующих авторизации. [YouTube Data API Python Quickstart](https://developers.google.com/youtube/v3/quickstart/python)
