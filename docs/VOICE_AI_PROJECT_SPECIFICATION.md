## 📌 Обзор проекта

### Краткое описание

**Voice AI Assistant** — это локальное приложение, которое обеспечивает взаимодействие пользователя с LLM моделями через голос. Система полностью работает на локальной машине без облачных сервисов, обеспечивая приватность и независимость.

### Ключевые характеристики

- **Полностью локальный**: Все модели (STT, LLM, TTS) запускаются на локальной машине
- **Открытый исходный код**: Опубликуется на GitHub после завершения MVP
- **Модульная архитектура**: Легко менять реализации компонентов
- **IPC-готов**: Другие приложения на ПК могут подключаться к сервису
- **Cross-platform**: Разработано с учётом Windows 10 (расширяемо на Linux/macOS)

### Целевая аудитория

- **Основной пользователь**: Разработчик-одиночка (автор проекта)
- **Потенциальные пользователи**: Разработчики, исследователи, люди, ценящие приватность
- **Стадия публикации**: Публикация на GitHub по завершении MVP

## 🎯 Видение и цели

### Основное видение

Создать персональный голосовой помощник, работающий полностью на локальной машине, позволяющий:
1. Говорить на русском языке
2. Получать ответы от мощной LLM
3. Слышать ответы синтезированным голосом
4. Использовать результаты из других приложений на ПК

### Долгосрочные цели

- ✅ **MVP (текущая фаза)**: Базовая функциональность STT→LLM→TTS
- 🔄 **Стабилизация**: Оптимизация, обработка ошибок, логирование
- 📈 **Расширение**: Добавить контекст, память разговора, различные режимы
- 🔗 **Интеграция**: Плагины для IDE, браузеров, текстовых редакторов
- 🚀 **Масштабирование**: Микросервис архитектура, API для сторонних приложений

### Проблемы, которые решает

| Проблема | Решение |
|----------|---------|
| Зависимость от облачных сервисов | Полностью локальное решение |
| Приватность данных | Никакие данные не выходят за пределы ПК |
| Дороговизна API вызовов | Бесплатное использование локальных моделей |
| Ограничения облачных сервисов | Полный контроль и гибкость |
| Необходимость интернета | Работает полностью offline |

## ✨ Функциональные требования

### MVP (Минимально жизнеспособный продукт)

#### Основной workflow

```
[Пользователь говорит] 
    ↓
[STT: Whisper распознаёт речь] 
    ↓
[LLM: Ollama + gemma-4-coder генерирует ответ] 
    ↓
[Парсинг ответа: извлечение чистого текста] 
    ↓
[TTS: XTTS-v2 синтезирует ответ] 
    ↓
[Проигрывание аудио пользователю]
```

#### Функции Фазы 1 (MVP)

- ✅ Запись голоса с микрофона
- ✅ Распознавание речи на русском (Whisper Large-v3)
- ✅ Передача текста в LLM (Ollama)
- ✅ Получение и парсинг ответа
- ✅ Синтез речи (XTTS-v2 или MeloTTS)
- ✅ Проигрывание ответа
- ✅ Логирование ошибок для отладки
- ✅ Минималистичный UI (Tkinter)
- ✅ Базовая IPC для других приложений

#### Функции Фазы 2+ (Future)

- 📅 Контекст разговора (история)
- 📅 Разные режимы работы (быстро/качественно)
- 📅 Встроенные скрипты (напоминания, автоматизация)
- 📅 Расширенная IPC с WebSocket
- 📅 REST API (FastAPI)
- 📅 Поддержка других языков

### Функциональные ограничения (MVP)

- ❌ Нет контекста между сеансами
- ❌ Нет истории разговора
- ❌ Нет встроенного web интерфейса
- ❌ Нет облачной синхронизации
- ❌ Нет расширений/плагинов
- ❌ Нет поддержки других языков (только русский в MVP)

### Основной workflow (User Journey)

```

      └─ Показать результат в UI

   ├─ Обработать (шаги B-D выше)
```

### Паттерны и принципы

#### 1. Инверсия управления через базовые классы

```python
# core/base.py
class STTProvider(ABC):
    @abstractmethod
    def load_model(self): pass
    @abstractmethod
    def transcribe(self, audio_path: str) -> str: pass
    @abstractmethod
    def unload_model(self): pass

class LLMProvider(ABC):
    @abstractmethod
    def generate(self, prompt: str) -> str: pass

class TTSProvider(ABC):
    @abstractmethod
    def synthesize(self, text: str) -> bytes: pass
```

Это позволяет легко менять реализации без трогания основного кода.

#### 2. Фабрика для создания провайдеров

```python
# core/__init__.py
def create_stt_provider(provider_name: str, **kwargs) -> STTProvider:
    providers = {
        "whisper": WhisperSTT,
        "vosk": VoskSTT,  # Добавляется позже
    }
    return providers[provider_name](**kwargs)
```

#### 3. Type hints везде

Все функции типизированы для работы с IDE и раннего обнаружения ошибок.

#### 4. Централизованная конфигурация

Все параметры в одном `config.py` — просто менять значения для экспериментов.

#### 5. Структурированное логирование

Все события логируются: ошибки, предупреждения, информация о процессе.

## 📦 Описание компонентов

### 1. STT (Speech-to-Text) компонент

**Файлы:**
- `core/stt.py` — основной класс WhisperSTT
- `core/preprocessing.py` — нормализация аудио
- `core/audio_input.py` — запись с микрофона

**Ответственность:**
- Загрузить модель Whisper
- Записать аудио с микрофона
- Нормализовать аудио (громкость, формат)
- Транскрибировать в текст
- Выгрузить модель из GPU при необходимости

**Интерфейс:**
```python
class WhisperSTT(STTProvider):
    def load_model(self, model_size: str = "large-v3")
    def transcribe(self, audio_path: str) -> str
    def unload_model(self)
```

**Параметры (config.py):**
```python
STT_PROVIDER = "whisper"
WHISPER_MODEL_SIZE = "large-v3"
WHISPER_DEVICE = "cuda"
WHISPER_LANGUAGE = "russian"
```

### 2. LLM (Language Model) компонент

**Файлы:**
- `core/llm.py` — основной класс OllamaLLM
- `core/ollama_client.py` — REST клиент к Ollama
- `core/prompt_manager.py` — парсинг ответов

**Ответственность:**
- Подключиться к локальному Ollama серверу
- Отправить промпт
- Получить и распарсить ответ (парсинг рассуждений)
- Логирование

**Интерфейс:**
```python
class OllamaLLM(LLMProvider):
    def generate(self, prompt: str) -> str
    def set_model(self, model_name: str)
```

**Параметры (config.py):**
```python
LLM_PROVIDER = "ollama"
OLLAMA_BASE_URL = "http://localhost:11434"
OLLAMA_MODEL = "gemma-4-coder"
PARSE_RESPONSE = True  # Извлекать только ответ
```

### 3. TTS (Text-to-Speech) компонент

**Файлы:**
- `core/tts.py` — основной класс XTSTTTS
- `core/audio_output.py` — проигрывание аудио
- `core/tts_utils.py` — утилиты TTS

**Ответственность:**
- Загрузить модель TTS
- Синтезировать текст в аудио
- Сохранить аудио файл
- Проигрыть аудио
- Выгрузить модель из GPU

**Интерфейс:**
```python
class XTSTTTS(TTSProvider):
    def load_model(self, language: str = "ru")
    def synthesize(self, text: str) -> bytes
    def unload_model(self)
```

**Параметры (config.py):**
```python
TTS_PROVIDER = "xtts"
TTS_DEVICE = "cuda"
TTS_LANGUAGE = "ru"
TTS_SPEAKER = "default"  # Выбор голоса
```

### 4. IPC (Inter-Process Communication) компонент

**Файлы:**
- `ipc/server.py` — сокет сервер
- `ipc/client.py` — сокет клиент для других приложений
- `ipc/protocol.py` — JSON-RPC протокол

**Ответственность:**
- Слушать на localhost:9999
- Принимать JSON запросы от других приложений
- Валидировать входные данные (Pydantic)
- Обрабатывать запрос (весь workflow STT→LLM→TTS)
- Возвращать JSON ответ

**API:**
```json
// Запрос
{
  "method": "transcribe_and_respond",
  "params": {
    "audio_file": "/path/to/audio.wav",
    "language": "russian"
  }
}

// Ответ успеха
{
  "status": "ok",
  "data": {
    "input_text": "привет мир",
    "output_text": "Привет! Как дела?",
    "audio_file": "/tmp/response_uuid.wav",
    "processing_time": 5.2
  }
}

// Ответ ошибки
{
  "status": "error",
  "error": "Invalid audio file"
}
```

**Использование из другого приложения:**
```python
from voice_ai.ipc.client import VoiceAIClient

client = VoiceAIClient()
result = client.transcribe_and_respond("/path/to/audio.wav")
print(result["output_text"])
```

### C. FAQ

**Q: Почему не использовать облачные API?**
A: Приватность, стоимость, независимость, offline работа.

**Q: Почему именно эти модели?**
A: Баланс качества, скорости, требований к ресурсам и популярности в сообществе.

**Q: Как это масштабируется?**
A: MVP компактен, но архитектура позволяет легко перейти на FastAPI, микросервисы, etc.

**Q: Что если моя GPU меньше?**
A: Можно использовать smaller модели (Whisper Small, MeloTTS) или CPU режим.

**Q: Как добавить новую модель?**
A: Создать класс, наследующий STTProvider/LLMProvider/TTSProvider, и зарегистрировать в фабрике.

**Q: Это готово к production?**
A: MVP фаза — для личного использования. Production requires дополнительная работа (фаза 1.0).
