# Тикет: Pause не работает на одиночном ролике YouTube

**Статус:** open
**Дата:** 2026-04-25
**Связанные команды:** `PauseCommand` / `ResumeCommand` (`commands/player_commands.py`), `media_keys.play_pause` (`system/media_keys.py`)

## Симптом

Голосовая команда «поставь на паузу» (и физическая мультимедиа-клавиша Play/Pause на клавиатуре) **не ставит на паузу** одиночный видеоролик YouTube, открытый в Яндекс.Браузере / Chrome.

При этом:
- На **плейлисте** YouTube — работает (и команда, и физическая клавиша).
- В **Spotify / VLC / прочих плеерах** — работает.
- Команды `чуть вперёд` / `чуть назад` (arrow-keys через фокус) — работают и на плейлисте, и на одиночном ролике.
- Команда `перемотай вперёд` (= `VK_MEDIA_NEXT_TRACK`) — работает только на плейлисте (что логично — переключает на следующий ролик).

## Причина

Это поведение **YouTube + Chromium**, не баг нашего кода. YouTube регистрирует Media Session API только для контента с навигацией (плейлисты, Music). Одиночный ролик media-session не публикует — `VK_MEDIA_PLAY_PAUSE` уходит «в никуда», и Windows не находит получателя. Подтверждается тем, что физическая клавиша ведёт себя так же.

Arrow-keys (`VK_LEFT`/`VK_RIGHT`) работают потому, что идут через **фокус активного окна**, а не через media-session — YouTube ловит их как обычный JS keydown.

## Варианты решения

### 1. Оставить как есть (no-op)
Pause работает для плейлистов, Spotify, VLC и т.д. Для одиночного ролика пользователь жмёт `K`/`Space` руками или добавляет видео в плейлист.

**Плюсы:** ничего не делать, текущая семантика «media-key для всех плееров» сохраняется.
**Минусы:** разочаровывающий UX в самом частом сценарии (открыл ролик с ютуба и хочет голосом поставить).

### 2. Добавить отдельную команду «пауза видео» через клавишу `K` (рекомендуется)
По аналогии с тем, как у нас разведены `перемотай вперёд` (= next track, media-key, глобально) и `чуть вперёд` (= arrow, фокус-зависимо).

- Новая команда `VideoPauseToggleCommand` (или две: `pause_video`/`resume_video`).
- Синонимы вроде «пауза видео», «останови видео», «продолжи видео» (≥2 слов по правилу).
- Реализация: `media_keys.press_key_k()` → `_press_key(VK_K=0x4B)` без флага EXTENDED.
- YouTube понимает `K` как Play/Pause toggle вне зависимости от плейлиста.
- `Space` тоже работает, но `K` надёжнее: `Space` промахивается, когда фокус на кнопке (лайк, подписка) — нажимает её вместо плеера.

**Плюсы:** чистая семантика, последовательно со skip-командами, пользователь явно выбирает фокус-зависимый путь.
**Минусы:** ещё одна команда в словаре; работает только когда YouTube в фокусе (но это и нужно — целевой сценарий полноэкранного просмотра).

### 3. Сделать `PauseCommand` «двойным»: media-key + `K`
Внутри `play_pause()` сначала шлём `VK_MEDIA_PLAY_PAUSE`, потом `VK_K`.

**Не рекомендуется.** `K` в любом другом активном окне (мессенджер, IDE, поле ввода в браузере) напечатает букву «к». Слишком легко выстрелить в ногу — плеер на паузу, но в чате коллеге улетела «к».

## Совет

**Вариант 2** — он последовательно с уже принятой архитектурой (media-key команды и focus-key команды разведены явно). Пользователь в полноэкранном YouTube говорит «пауза видео» и получает ожидаемое поведение; в Spotify / VLC продолжает использовать «поставь на паузу». Никакой магии и фрагильных эвристик «определить, какой плеер сейчас активен».

## Замечание для исполнителя

- Не забыть про правило ≥2 слов в синонимах (`commands/registry.py:32`).
- Не забыть `ack_after` (можно переиспользовать `pause_after.wav` / `resume_after.wav`).
- Не забыть пересобрать snapshot: `python scripts/dump_commands_snapshot.py`.
- `VK_K` (0x4B) — обычная буквенная клавиша, **не** добавлять в `_EXTENDED_VKS`.
