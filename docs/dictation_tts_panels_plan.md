# План: панели STT-диктовки и TTS-озвучки в PySide6-UI

> Статус: **черновик плана** (обсуждение), не журнал изменений.
> Цель: добавить в `ui/pyside6/` две самостоятельные функции на базе уже
> готовых подсистем Whisper STT и Silero TTS, не трогая голосового ассистента.

---

## 1. Цели и сценарии

Две новые функции графического интерфейса:

1. **STT-диктовка** — надиктовывать текст голосом, результат попадает **в поле
   ввода активного окна** (туда, где стоит курсор): заметки в любое приложение,
   текст команд/вопросов в чаты и т.п.
2. **TTS-озвучка** — ввести/вставить текст и **озвучить его** через колонки
   и/или **сохранить в аудиофайл**.

Обе функции переиспользуют существующий `VoicePipeline` (микрофон, Whisper,
Silero) и не дублируют движки.

### Согласованные решения (дефолты плана)

| Тема | Решение | Обоснование |
|---|---|---|
| Запуск диктовки | **Без клавиатуры:** плавающая экранная кнопка «Старт/Стоп» (мышь) + голосовая фраза-активатор; глобальный хоткей `Ctrl+Alt+D` — запасной | цель фичи — работать мышью/голосом, не отвлекаясь на клавиатуру; кнопка/окно не перехватывают фокус, иначе вставка уйдёт не туда |
| Вставка текста | **Буфер обмена + `Ctrl+V`** с восстановлением старого буфера | надёжно для кириллицы; посимвольная эмуляция хрупка (раскладки/Unicode) |
| Режим диктовки | **Непрерывный**: сегменты вставляются по мере распознавания | естественно для длинного текста |
| Параллельность | **Нет.** На время работы инструмента wake-word ставится на паузу | пользователь сидит за ПК, одновременность не нужна |
| TTS-движок | **Silero (CPU)**, без GPU-swap | основной движок пользователя; Whisper остаётся в VRAM |
| Формат аудио | **WAV PCM16** (опц. FLAC); MP3 — позже (нужен внешний кодек) | без новых зависимостей |
| Размещение в UI | **Вкладки** в главном окне: Дашборд / Диктовка / Озвучка | не плодит окна; дёшево |

## 3. Функция 1 — STT-диктовка

### 3.1 Поток работы
1. Пользователь ставит курсор в поле ввода нужного приложения.
2. Жмёт глобальный хоткей `Ctrl+Alt+D` → ассистент ставит wake-word на паузу,
   проигрывает короткий beep-«старт», показывает индикатор «Диктую → активное окно».
3. Цикл: `record_until_silence` (короткий `pause_threshold`) → Whisper → сегмент.
4. Каждый распознанный сегмент:
   - дописывается в историю на вкладке «Диктовка» (для контроля);
   - вставляется в активное окно через clipboard + `Ctrl+V`.
5. Повторный `Ctrl+Alt+D` (или кнопка «Стоп») завершает сессию, возвращает
   wake-word в прежнее состояние.

### 3.2 Профиль распознавания (отличается от команд)
Диктовка — связный текст, поэтому декодер настраивается иначе, чем для команд:

| Параметр | Команды (сейчас) | Диктовка |
|---|---|---|
| `pause_threshold` (VAD) | 5.0 | **1.2–1.5 с** (сегмент ≈ предложение) |
| `max_duration` (VAD) | 60 | **30 с** на сегмент |
| `initial_silence_timeout` | 8 | большой/∞ (ждём начала) |
| `beam_size` | default | **5** (точнее на длинных фразах) |
| `temperature` | fallback-лесенка | **0.0** (детерминированно) |
| `condition_on_previous_text` | False | подавать **предыдущий сегмент как `initial_prompt`** (согласование пунктуации/регистра без авто-drift) |
| модель | `large-v3-turbo` | опционально `large-v3` ради точности (есть `models/large-v3.pt`) |

Капитализация: первую букву сегмента поднимать, если предыдущий закончился на
`.!?`; сегменты склеивать пробелом.

### 3.3 Вставка в активное окно
- Текст кладём в `QClipboard` (в UI-потоке), посылаем `Ctrl+V` через `pyautogui`/`pynput`.
- **Сохраняем и восстанавливаем** прежнее содержимое буфера.
- Режим вставки настраиваемый: «в активное окно» / «только в поле истории» /
  «в буфер обмена». Это снимает риск «текст ушёл не туда».

### 3.4 Новый код
- `VoicePipeline.dictation_loop(on_segment, stop_event, *, profile)` — цикл
  записи-распознавания со стоп-флагом и колбэком на сегмент. На время работы
  ставит wake-listener на паузу.
- расширить `WhisperSTT.transcribe(...)` опциональными kwargs
  (`beam_size`, `temperature`, `initial_prompt`-override), чтобы команды
  и диктовка использовали разные профили.
- `system/text_injector.py` — clipboard-set + paste-keystroke + restore.

### 3.5 Способы запуска — без клавиатуры

> **Главная идея фичи:** освободить руки от клавиатуры и работать **мышкой/голосом**.
> Поэтому приоритет триггеров обратный «обычному»: глобальный хоткей — лишь
> запасной вариант, а основные способы запуска — экранная кнопка и голос.

**A. Плавающая экранная кнопка «Старт/Стоп» (мышь, основной способ).**
Полупрозрачный frameless / always-on-top виджет поверх всех окон с одной кнопкой,
меняющей состояние (▶ старт / ⏹ стоп) и подсвечивающей активную запись.
- Не перехватывает фокус (`Qt.WindowDoesNotAcceptFocus` / `WA_ShowWithoutActivating`) —
  иначе вставка уйдёт в наш виджет, а не в целевое окно.
- **Перетаскиваемый** мышью, позиция и размер сохраняются в конфиг.
- Опционально прячется в трей / сворачивается в маленькую точку.
- Базируется на тех же приёмах, что `ui/pyside6/widgets/wake_hint_overlay.py`
  (frameless, on-top, click-through-кроме-кнопки).

**B. Голосовая активация (руки свободны полностью).** См. ниже — фраза-активатор.

**C. Глобальный хоткей `Ctrl+Alt+D` — запасной.** Остаётся, но не основной.

#### Голосовая активация (как «Шурочка» для команд)

> ⚠️ **Триггер обязан быть ≥2 слов и отличительным** (память
> `feedback_two_word_commands`). Однословное «запиши» — частое слово, будет
> ложно срабатывать; цена ложного срабатывания здесь выше обычного —
> распознанный текст начнёт вставляться в активное окно. Нужны явный сигнал
> старта и лёгкая отмена.

Два пути (можно совместить):

- **Путь A — диктовка как голосовая команда (рекомендуемый старт).**
  Новая команда в реестре, напр. «печатай в окно» / «диктуй текст».
  Поток: `Шурочка → печатай в окно` → `dictation_loop` со вставкой в активное окно.
  Плюсы: переиспользует `CommandRouter`, правило ≥2 слов, ack-фразы; минимальный
  риск ложных (защита словом «Шурочка»). Минус: двухступенчато.
- **Путь B — отдельная фраза-активатор (без «Шурочка»).**
  Расширить `WakeWordListener` до нескольких триггеров → разных действий:
  «Шурочка» → команды; отдельная фраза (напр. «начни диктовку» / «запиши в окно»)
  → сразу диктовка. Плюс: целевой UX в одно действие. Минусы: выше риск ложных
  (нужна отличительная многословная фраза), мульти-матчер в листенере.

Общие требования: дежурный режим (listener) включён; латентность детекта ~до
`WAKE_WORD_SCAN_WINDOW` (4 с); голосовой стоп («закончи диктовку») + кнопка/Esc
как страховка.

Конфиг (черновик): `[dictation]` → `voice_activation = "command" | "phrase" | "off"`,
`activation_phrase = "начни диктовку"`, `stop_phrase = "закончи диктовку"`,
`floating_button = true`, `floating_button_pos = [x, y]`.

## 4. Функция 2 — TTS-озвучка

### 4.1 Поток работы
1. Вкладка «Озвучка»: текстовое поле, выбор голоса, кнопки **«Проиграть»** и
   **«Сохранить…»**, индикатор «синтез N/M чанков», кнопка «Стоп».
2. Перед синтезом — нормализация текста (см. 4.2).
3. Если латиница найдена — плашка-предупреждение («будет транслитерирована»).
4. «Проиграть» → синтез + проигрыш; «Сохранить…» → диалог пути, склейка в один WAV.

### 4.2 Нормализация текста (критично для качества)
- **Числа → слова** через `core.reminders.num_to_words` (для панели включить
  бэкенд `num2words` — полный диапазон, даты, склонения). Util
  `normalize_text_for_tts(text)`: regex находит числовые токены и заменяет словами.
- Латиница — уже транслитерится в `SileroTTS`, но в панели **предупреждаем** пользователя.
- Ручное ударение: дать подсказку, что омографы можно править через `+`
  (`за+мок` / `замо+к`).

### 4.3 Чанкинг длинного текста (главный новый код)
Сейчас `SileroTTS.synthesize` **обрезает** на ~900 символов. Для панели нужно:
1. разбить текст по предложениям (`.!?…`), сгруппировать в чанки ≤ ~800 символов;
2. синтезировать каждый чанк;
3. **склеить** массивы с тишиной-разделителем (~150 мс между предложениями,
   ~300–400 мс между абзацами);
4. записать один итоговый WAV.

Реализация: либо добавить `SileroTTS.synthesize_to_array(text)` (без записи на
диск) и собирать numpy-массивы, либо читать-конкатенировать чанковые WAV'ы.
Предпочтительно первое (чище, без лишних файлов).

### 4.4 Параметры Silero (рекомендации)
| Параметр | Значение | Комментарий |
|---|---|---|
| `sample_rate` | **48000** | максимум качества (уже стоит) |
| `speaker` | dropdown: `xenia`/`baya`/`kseniya`/`aidar`/`eugene` | выбор голоса в панели |
| `put_accent`, `put_yo` | `True` | правильные ударения и «ё» |
| `intensity` (v5) | `3` | выразительность |
| скорость/паузы | через **SSML-подмножество** (`<break>`, `<prosody rate>`) | продвинутый режим; не менять питч ресэмплингом |

### 4.5 Новый код
- `VoicePipeline.synthesize_long(text, *, speaker, save_path=None, play=False, on_progress=None)`
  — нормализация → чанкинг → склейка → (проигрыш | сохранение).
- `core/tts_chunking.py` — разбивка по предложениям и склейка с паузами.
- `core/text_normalize.py` — числа→слова для TTS (обёртка над `num_to_words`).

## 6. Изменения в UI (`ui/pyside6/`)

- `dashboard.py`: завернуть текущий layout в `QTabWidget` → вкладки
  **Дашборд / Диктовка / Озвучка**.
- `widgets/dictation_panel.py`: статус, кнопка старт/стоп, поле истории сегментов,
  выбор режима вставки, подсказка про способы запуска.
- `widgets/dictation_button.py`: **плавающая полупрозрачная кнопка «Старт/Стоп»**
  поверх всех окон (frameless, on-top, не перехватывает фокус, перетаскиваемая) —
  основной способ запуска мышью. Приёмы — как в `widgets/wake_hint_overlay.py`.
- `widgets/tts_panel.py`: поле текста, выбор голоса, «Проиграть»/«Сохранить»/«Стоп»,
  прогресс чанков, плашка-предупреждение про латиницу.
- `bridge.py`:
  - jobs: `dictation_start`, `dictation_stop`, `tts_play`, `tts_save`;
  - signals: `dictation_segment(str)`, `dictation_state(str)`,
    `tts_progress(int, int)`, `tts_done(str|None)`, `tts_error(str)`;
  - глобальный хоткей диктовки через `HotkeyListener` (запасной триггер).

## 8. Риски и открытые вопросы

- **Вставка не туда / фокус.** Если активное окно не текстовое — `Ctrl+V`
  ничего не даст или вставит в неожиданное место. Митигировать индикатором
  и режимом «history_only» как безопасным дефолтом для первой проверки.
- **Антивирус/UIPI.** Синтетический ввод в окна с повышенными правами (admin)
  может игнорироваться, если наш процесс без прав. Документировать.
- **MP3.** Требует ffmpeg/кодека — вынесено за scope первого этапа.
- **`large-v3` для диктовки** заметно медленнее turbo — оставить переключаемым.
- **SSML-скорость** — проверить поддержку в конкретной версии Silero v5_4_ru.
